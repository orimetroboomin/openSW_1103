## **1. 사업 개요**

| 항목 | 내용 |
| :--- | :--- |
| 사업명 | 바로대여 대여 신청·반납 표 관리 앱 개발 |
| 공모 목적 | 본 사업을 수행할 개발팀(제안사)을 선정한다. 발주사는 개발하지 않고, 선정된 개발팀이 앱을 개발해 납품한다. |
| 추진 목적 | 대여 신청과 반납 내역을 표(테이블)로 한눈에 관리하여 물품 수량 착오와 중복 대여를 없앤다. |
| 사업 범위 | 날짜별 대여 가능 수량 조회, 대여 신청, 반납 수량 등록, 대여 현황 조회 (4개 기능) |
| 개발 환경 | Python, Streamlit, pandas, CSV 파일 (외부 서버·DB 없음) |
| 시연 방식 | 가상 데이터를 사용해 개발자 PC에서 로컬 실행 |
| 계약 방식 | 제안서 평가 후 우선협상대상자 선정 |

### **1.1 추진 배경**
- 행사(축제, 동아리 행사, 기업 행사 등)에서 쓰는 물품(의자, 테이블, 천막, 음향장비 등)은 날짜가 겹치면 수량이 모자라기 쉽다.
- 대여와 반납을 사람이 기억하거나 메신저로 주고받으면 남은 수량을 잘못 안내하는 일이 생긴다.
- 대여 신청과 반납을 하나의 표로 관리하면 누가, 언제, 몇 개를 빌려 갔고 몇 개가 돌아왔는지 바로 확인할 수 있다.

### **1.2 기대 효과**

| 구분 | 현재 | 개선 후 |
| :--- | :--- | :--- |
| 재고 확인 | 담당자 기억·수기 메모에 의존 | 날짜를 고르면 가능 수량이 표로 표시 |
| 대여 신청 | 수량 초과 여부를 사후에 발견 | 신청 시점에 초과 여부를 차단 |
| 반납 확인 | 일부 반납 시 잔여 수량 파악 어려움 | 반납 수량을 누적 기록하고 미반납 수량을 자동 계산 |
| 현황 파악 | 전체 내역 취합에 시간 소요 | 대여 현황 표 한 화면에서 조회 |

### **5.2 기능별 상세**

#### **F-01 날짜별 대여 가능 수량 조회**
- **사용자**: 대여 담당자, 운영 관리자
- **입력**: 조회 날짜 (단일 날짜 선택)
- **처리**: 물품별로 대여 가능 수량 = 보유 수량 − 해당 날짜에 대여 중인 미반납 수량을 계산한다. 대여 중인 건은 대여일 ≤ 조회일 ≤ 반납일이면서 아직 반납되지 않은 수량만 센다.
- **결과**: 물품 ID, 보유 수량, 대여 중 수량, 대여 가능 수량을 담은 표를 표시한다. 가능 수량이 0이면 “대여 불가”로 표시한다.

#### **F-02 대여 신청**
- **사용자**: 대여 담당자
- **입력**: 물품 ID(선택), 대여일, 반납일(예정), 신청 수량
- **처리**: ① 입력값 검증 (수량은 1 이상의 정수, 반납일 ≥ 대여일) ② 대여일~반납일 전체 기간 중 가능 수량이 가장 적은 날을 기준으로 신청 수량이 그 이하인지 확인 ③ 통과하면 신청 건을 신규 번호로 CSV에 저장
- **결과**: 성공: “신청이 등록되었습니다(신청번호 표시)”. 실패: 거부 사유(수량 초과, 날짜 오류, 미입력)를 화면에 표시하고 저장하지 않는다.

#### **F-03 반납 수량 등록**
- **사용자**: 대여 담당자
- **입력**: 신청 건 선택, 이번 반납 수량
- **처리**: ① 이번 반납 수량이 1 이상이고 신청 수량 − 기존 누적 반납 수량 이하인지 확인 ② 통과하면 누적 반납 수량에 더한다 ③ 누적 반납 수량이 신청 수량과 같아지면 상태를 “반납완료”로, 그보다 적으면 “일부반납”으로 바꾼다 ④ 반납된 수량은 등록 즉시 대여 가능 수량에 반영한다
- **결과**: 성공: 누적 반납 수량, 미반납 수량, 상태를 보여 준다. 실패: 초과 반납 사유를 안내하고 저장하지 않는다.

#### **F-04 대여 현황 조회**
- **사용자**: 대여 담당자, 운영 관리자
- **입력**: (선택) 상태 필터(전체/대여중/일부반납/반납완료), 물품 ID 필터
- **처리**: 신청 이력 전체를 읽어 신청번호별로 신청 수량, 누적 반납 수량, 미반납 수량, 상태를 계산한다. 반납 예정일이 지났는데 미반납이 남은 건은 “기한 초과”로 표시한다.
- **결과**: 대여 현황 표 (신청번호, 물품 ID, 대여일, 반납일, 신청 수량, 반납 수량, 미반납 수량, 상태). 조건에 맞는 건이 없으면 “조회 결과가 없습니다”를 표시한다.

## **6. 완료 기준**

기능별로 정상 상황과 예외 상황을 모두 확인한다. 모든 항목이 “통과”여야 납품 완료로 인정한다.

| 기능 ID | 구분 | 확인 시나리오 | 기대 결과 | 통과 |
| :--- | :--- | :--- | :--- | :--- |
| F-01 | 정상 | 보유 20개, 해당일 대여 중 5개인 물품의 날짜를 조회한다. | 가능 수량 15개 표시 | ☐ |
| F-01 | 예외 | 해당일에 대여 가능 수량이 0인 물품을 조회한다. | “대여 불가” 표시, 오류 없이 표 출력 | ☐ |

| F-03 | 정상 | 신청 수량 전부를 반납한다. | 상태 “반납완료”, 미반납 0 | ☐ |
| F-03 | 정상 | 신청 수량의 일부만 반납한다. | 상태 “일부반납”, 미반납 수량 정확히 표시 | ☐ |
| F-03 | 정상 | 일부 반납 후 나머지를 다시 등록한다. | 누적 반납이 합산되어 “반납완료” | ☐ |
| F-03 | 예외 | 남은 미반납 수량보다 많이 반납 등록한다. | 등록 거부와 사유 표시 | ☐ |
| F-03 | 예외 | 이미 반납완료된 건에 다시 반납을 등록한다. | 등록 거부 | ☐ |
| F-03 | 정상 | 반납 등록 직후 같은 물품을 다시 신청한다. | 반납된 수량만큼 즉시 대여 가능 | ☐ |
| F-04 | 정상 | 상태 필터를 바꿔 조회한다. | 필터에 맞는 건만 표시 | ☐ |
| F-04 | 예외 | 반납 예정일이 지났는데 미반납이 있다. | “기한 초과”로 구분 표시 | ☐ |
| F-04 | 예외 | 조건에 맞는 건이 없다. | “조회 결과가 없습니다” 표시 | ☐ |
| 공통 | 예외 | CSV 파일이 없거나 비어 있다. | 앱이 멈추지 않고 안내 문구 표시 | ☐ |

| ① 가능 수량 조회 | F-01 | 날짜 선택, 가능 수량 표 |

### **8.3 기술 제약**

- 데이터는 CSV로만 저장하며 실행 폴더의 data/ 아래에 둔다.
- 반드시 `pip install -r requirements.txt` 후 `streamlit run app.py` 한 줄로 실행되어야 한다.

## **10. 업무 규칙 및 가상 데이터 정의**

### **10.1 업무 규칙**
- R-1: 대여 가능 수량 = 보유 수량 − (해당 날짜에 대여 기간이 걸치는 건의 미반납 수량 합계)
- R-2: 대여 기간은 대여일과 반납일(예정일)을 모두 포함한다.
- R-3: 일부 반납을 허용한다. 반납은 여러 번에 나눠 등록할 수 있고 누적한다.
- R-4: 반납 등록된 수량은 그 즉시 다시 대여할 수 있다. 아직 반납 등록되지 않은 수량은 빌릴 수 없다.
- R-5: 상태는 반납 수량 0이면 “대여중”, 0 초과 신청 수량 미만이면 “일부반납”, 같으면 “반납완료”로 한다.
- R-6: 반납 예정일이 오늘보다 앞서고 미반납이 남아 있으면 “기한 초과”로 표시한다.
